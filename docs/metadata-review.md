## 已由官网补齐的气象定义（F）

附件1`description`中英文均将小时观测时间定义为北京时间UTC+8；`instructions`将9999.9列为缺失值。

| QC码 | 官网给定含义 |
| --- | --- |
| 0 | 正确 |
| 1 | 可疑 |
| 2 | 错误 |
| 4 | 插补数据 |
| 8 | 数据缺失 |
| 9 | 未进行质量控制 |

这套解释适用于文件中实际存在的QC字段。FLUX没有相应QC列，不能因此给它默认赋0。
QC=4意味着提供方已标插补，不能称为未经处理的直接观测；本项目不新增插补或覆盖原值。
原始空白与大写`NAN`的出现是文件事实；其与QC或具体缺测原因的对应关系没有因此自动得到说明。

官网中文坐标及结构化south/north为28.86°N，英文说明为28.26°N；经度均写85.29°E。
在作者纠正前不裁决单一纬度。官网说明该站距受灾口岸约65km，并明确限定其区域背景用途；不能用站点降水直接替代灾区局地降水或直接认定触发机制。

附件2`instructions`明确温度单位是摄氏度。无需再凭负数猜单位，也不再减273.15。
CDS上游默认K与附件已提供的℃不是同一处理阶段。日统计UTC偏移和县域汇总方式仍未确认。

## 本地字段与元数据的证据边界

附件1：24个CSV文件名和表头给出组别、年份、高度/深度、单位、QC列；没有小时区间起止或降水清零规则。
附件2：21份Excel表头与日期/县名一致，包内旧版Word给出ERA5-Land CDS来源；单凭表头不能确认日界线。
附件3—8已复查内嵌DOCX、XML、PRJ/CPG、TIFF、NetCDF全部属性及DBF头；详细证据见[本地空间元数据复核](spatial-metadata-evidence.md)。

特别收紧以下旧用语：

- `影像Time`和`解译Time`的存储值及字段名可核验，但XML没有业务定义；日志有CalculateField赋日期记录。不能直接称为影像采集日或实际解译日，更不能称为灾害发生日。
- DEM的20260826/171843对应`lineage/Process`中的Clip操作。它是处理记录；不是采集日期，也不证明灾前/灾后地形状态。
- `人口数/户数≈户规模`只是数值关系；不能自行把人口数字段命名为户籍人口或家庭户人口，也不能断言与合计的差值原因。
- 金字塔的NEAREST属性不能代表原始土地覆盖生产/配准所用算法。
- RGI6/7日期字段先保留存储值，业务含义和特殊日期编码须另查对应版本字典；不直接认定为影像采集日。
