## 当前最有价值的疑问

下列定义优先从本地属性与公开文档查证，确需登录/申请时再请用户操作，不让用户代替程序完成可自动化检查。

1. **第3项**：文件内每个降水变量代表哪段累计或平均，起止时刻是什么，f000有哪些有效量？本轮说明能明确来源预报，但仍不能把不同累计口径直接相加。
2. **第4项**：d02到底有多少Times，是否含PBLH、温湿风和可用的垂直坐标？44层是模式设置，不能据此宣称发布文件含全部三维量。RAINNC/RAINC是否齐全，是否存在重启？
3. **预报可得性**：第3项起报时刻已知，其公开发布延迟仍待查；WRF/TPCSM什么时候实际生成，是否只用于事后重建？起报、有效、生成、发布四种时间分别记录。
4. **灾害链时刻**：冰崩起始、泥石流触发、到达具体断面/口岸、报告各是什么时间和时区？赛题10:30不自动赋给其中任一阶段。若官网没有，优先补带来源和地点的官方调查/通报或观测记录。
5. **源区与流路**：第1、24项是否覆盖尼泊尔源区至口岸的整条通道？如果只裁了吉隆县，仍需补跨境范围，不能据中文标题认定已经覆盖。
6. **过程验证**：是否有本次灾害的范围边界、堆积厚度、流量、到达时刻或灾前灾后遥感？这些比再增加一套重复气象格点更有助于二至四问检验。若没有，明确采用情景与敏感性分析。

下表是拟采用的简单基线与交付标准，不代表模型已经完成或有效性已经验证。数据补齐后先完成四问结果，再增加复杂度。

| 问题 | 首版方案 | 必交结果 | 不能越过的边界 |

| 一：关联与前5因素 | 现有长期观测背景、同刻多高度结构，加局地气象过程；在明确比较对象后按效应幅度、物理证据和敏感性进行透明筛选 | 5因素表，逐项给出指标公式、数值依据、物理解释和限制；背景/事件过程图、样本覆盖和QC敏感性表 | 塔站变量互相关不能直接替代灾害关联；单次事件只能形成案例证据，不能声称普适因果前5名 |
| 二：触发评估 | 地形、物源、水源三条件的可解释情景评估；根据可用参数选择简单物理判据或明确规则，区分文献阈值与本地校准 | 评估地图、参数单位与来源、临界条件和敏感性结果 | 无可靠负样本不强造二分类；历史灾点无事件时标，不用于伪造触发阈值准确率 |
| 三：预报与95%区间 | 使用起报与有效时间明确的预报场、第二问阈值及流路；区分阈值首次越界时间与传播到达时间，传播参数不确定性 | 起报/有效/可得时间表，触发时间区间、提前量、覆盖范围图及区间定义 | 参数集合的95%情景范围不自动等于频率学95%置信区间或已校准预测区间。若无法满足赛题要求，显式标为未满足，并列验证缺口；事后模拟只称回溯试验 |
| 四：过程仿真 | 在地形和通道明确后先做可复现的简化运动/汇流模型，使用少量有来源或明确标为情景的参数 | 可运行程序、参数表、时间序列、传播路径/范围快照和动画；保存守恒/步长检查及敏感性结果 | 普通流向着色图不能冒充泥石流动力学；不把未经标定的速度、深度、范围写成实测重建 |

本轮用户说明的要求为“包括程序、数据（赛题中的原始数据除外）和结果等与竞赛相关的其他所有文件”。当前尚未收到正式提交细则，文件命名、压缩格式/上限、匿名规则及补充官方数据是否属于豁免原始数据，需逐项核对；不能凭此句自行规定。

  environment.win-64.lock.txt
  scripts/                     # 所有实际使用的分析、模型、制图和打包程序

打包时从实际用到的程序和数据生成清单，不把所有缓存都塞进去。原8包及重复解压副本按用户说明排除；用于计算的派生数据、补充数据（在规则与许可允许下）、关键中间结果和最终结果保留。Git对 `data/`、`output/` 的忽略规则只服务版本管理，不能当成支撑材料的排除规则。不得包含本机环境、账号令牌、临时下载工具、无关实验或他人个人路径。

代码根据脚本位置找项目根目录，所有数据/输出位置用项目相对目录；可执行工具由PATH或当前解释器发现。日志可以记录运行环境事实，但不能作为运行时硬编码依赖。随机过程固定种子并保存参数，尚未使用随机模型的描述分析不伪造“种子保证独立性”。

给论文队友的每张图/表应附：所属题号、输出文件、对应脚本/配置、可直接引用的结论、单位、样本口径、局限和版本号。SVG/PNG与CSV配套，避免队友从截图抄数；最终论文数值与支撑结果逐项核对。本项目不承担论文正文代写，但承担支撑其结果的程序、方法说明与证据。
